# RouteWeaver · macOS 分流

RouteWeaver 是基于 Mihomo 的独立 SwiftUI 应用。默认只在本机启动 HTTP / SOCKS5 混合代理，不运行特权 helper，不安装系统扩展，也不会自动修改默认路由、系统代理或 DNS。它不内置第三方节点或 Mihomo 可执行文件。

## 构建与启动

需要 macOS 13+、支持 Swift 5.9 的 Xcode 或 Command Line Tools，以及可信来源的 [Mihomo](https://github.com/MetaCubeX/mihomo/releases) v1.19.27 或更新稳定版内核。为 Mac 选择正确架构的 Darwin 二进制，解压到固定目录并赋予执行权限。建议核对上游提供的校验值；应用会执行你选择的文件，不要把来历不明的程序选成内核。

```bash
cd RouteWeaver
./Scripts/build-app.sh
open dist/RouteWeaver.app
```

脚本会运行 Swift 单元测试，编译本机架构的应用，再做本地临时签名。它不安装应用、不下载内核，也不进行公证。

## 场景一：USB + Wi-Fi/网线 + 两组出口

1. 把 USB 网卡和主网卡接好。用 `networksetup -listallhardwareports` 对照硬件端口名和 BSD 设备名，例如 USB 为 `en5`，Wi-Fi 为 `en0`。不要凭编号猜。
2. 在应用选择双网卡模板，分别选择 Claude 的 USB 网卡和国内流量的网卡。另外两套模板分别把两类直连绑到同一张网卡，或改为仅 Google / YouTube 使用 A、社交媒体使用 B。
3. 填写 Mihomo **proxy-provider** 订阅（是包含 `proxies:` 的 YAML 节点表，不是完整 Clash 配置或 Base64 节点列表）。L 可以用单独的订阅；也可以和 A/B 填同一个地址，用互不混淆的节点名称区分用途；同一订阅下 L 必须写单独的正则。不同正则仍可能匹配到同一个节点，请在组列表确认。留意代理提供商是否允许这样连接。
4. 用正则匹配节点名。示例：L 组匹配 `(?i)前置|入口|relay`，A 匹配 `(?i)美国|united states|\bUS\b`，B 匹配 `(?i)香港|hong kong|\bHK\b`。请以实际节点名为准。
5. 打开相应组的自动测速，应用用 Mihomo URL-test 及 provider 健康检查选路。用手动组时在应用里选节点。测速反映的是测试目标的连通性/延迟，不等于下载带宽。测速会通过所配置的网络和代理发出真实请求。
6. 先校验，再启动。在需要的应用内设置本机 HTTP/SOCKS5 代理；也可在 **系统设置 → 网络 → 当前网络服务 → 详细信息 → 代理** 中手动配置 HTTP 和 HTTPS 代理。使用应用显示的 `127.0.0.1` 端口。停用 RouteWeaver 前，先恢复手动设置的系统代理，避免留下一项指向已停止的本机代理。别让其他客户端的系统代理或 TUN 同时争用配置。

| 优先级 | 目标 | 实际出口 |
| --- | --- | --- |
| 1 | 模板列出的 Claude / Anthropic 服务域名 | USB 直连 |
| 2 | Google 和列出的社交媒体服务 | 节点 L → A 出口，例如美国 |
| 3 | 中国域名或中国目标 IP | 指定 Wi-Fi / 网线直连 |
| 4 | 其余 | 节点 L → B 出口，例如香港 |

把 `dialer-proxy` 写到最终出口代理上，而不是把节点按顺序平铺在测速组里。握手是 **本机 → L → A（或 B）**，站点看到的通常是 A/B 的出口。L 自己不再经 A 或 B；相同订阅 URL 时软件也将 L、A、B 分别导入，不复用代理对象。选中的组无可用节点时不会被配置成默认切换到直连。参见 [Mihomo dialer-proxy](https://wiki.metacubex.one/en/config/proxies/dialer-proxy/)。

## 范围和验证

- 分流只作用于实际送到 Mihomo 的请求；Claude 按域名匹配，不保证覆盖桌面应用发出的所有独立连接。忽略系统代理的软件、直连 UDP/QUIC 和全机透明代理不在这个版本的范围内。
- 出站直连套接字绑在指定网卡，DNS 不保证按网卡隔离。内核启动前会校验可用网卡，运行时检测到网卡消失会停止内核，不自动改用另一网卡。这不是系统级 kill switch，也不保证其他应用不会绕过代理。
- Mihomo 校验/启动可能下载规则数据以及访问你填的订阅。应用为每次运行创建独立缓存，避免切换方案后误用上次的节点；因此需要订阅和规则源可达。L 的物理出口和订阅拉取绑定主网卡。不要分享包含订阅令牌的配置或 JSON；日志会遮挡常见的 HTTP(S) URL，但并非通用凭据清理工具。
- 两张网卡实测：两条直连分别观察物理网卡的连接；对 A/B 各测一次出口 IP，加上测试代理 L 的连接日志确认第一跳；分别用空匹配、拔掉 USB 网卡、禁用 L 来验证预期失败。代理无关 app 和系统 DNS 请单独验收，不以导出配置或单元测试代替实机结果。
